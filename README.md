# NixOS config

Flake-based NixOS configuration for my machines.

> [!NOTE]
> This refactor is LLM-generated. I'm too much of a noob right now to bother with learning NixOS fairly deeply, I currently just want to have my laptop setup be easily portable to another machine, along with the dotfiles.

## Hosts

- `laptop` — current machine.
- `desktop` — planned; add its generated hardware configuration before
  enabling it in `flake.nix`.

## Layout

```text
flake.nix              # inputs and hosts
hosts/<name>/          # machine-specific config + hardware scan
modules/               # shared system configuration
home/<user>/           # Home Manager user configuration
```

- `modules/core.nix` — system basics, networking, locale, SSH
- `modules/hardware.nix` — graphics, Bluetooth, power
- `modules/desktop.nix` — Niri, greetd, fonts
- `modules/development.nix` — Docker, MySQL, PostgreSQL, nix-ld
- `modules/home-manager.nix` — Home Manager integration
- `modules/packages.nix` — system packages
- `modules/users.nix` — user account
- `home/arvingarciabtw/` — Home Manager user config, Niri/Noctalia, and
  dotfiles

`hosts/<name>/hardware-configuration.nix` is generated by `nixos-generate-config`.
Do not copy it between machines.

## Commands

```bash
# Build without changing the running system
nixos-rebuild build --flake .#laptop

# Apply
sudo nixos-rebuild switch --flake .#laptop

# Update inputs
nix flake update

# Format
nix fmt
```

Always use `--flake`; `/etc/nixos` may still be a stale copy.

Home Manager runs as part of the same switch. On the first activation it links
the managed configs. Conflicting regular files are moved aside as
`*.hm-backup`; existing symlinks (for example, from `stow`) are not and must be
removed before switching. Niri and Noctalia config changes now require a
rebuild. Noctalia runtime settings (theme, wallpaper, lockscreen layout) stay
writable in `~/.local/state/noctalia/settings.toml`; the repo only seeds that
file if it does not exist.

## Dotfiles

Home Manager owns the curated dotfiles:

- Linked from the repo: Ghostty, tmux, tmuxinator, Yazi keymap, fastfetch
  (including its logo), fontconfig, `.gitconfig`, and the Bash environment.
- Seeded once and left writable: btop, ditto, nom, Neovim, and OpenCode.
  These applications rewrite their own files. To reset one, remove its live
  directory and rebuild. OpenCode itself is still installed with its own
  installer; this repo only seeds its config.

Not migrated: fish, Hyprland, Waybar, Zellij, pgcli, posting, and dunst. They
are unused here.

Secrets are not in the repo. Shell secrets live in
`~/.config/secrets/shell.env` (mode 600) and are loaded by `.bashrc` if the
file exists. Create it on a new machine with any local database DSNs.

Rollback: pick the previous generation in the systemd-boot menu, or run:

```bash
sudo nixos-rebuild switch --rollback
```

## Adding a machine

This example adds the `desktop`.

1. Boot the NixOS ISO on the new machine and run
   `nixos-generate-config --root /mnt`.
2. Copy the generated hardware file to
   `hosts/desktop/hardware-configuration.nix`.
3. Create `hosts/desktop/default.nix` with the same shared modules as the
   laptop, plus the desktop's hostname, state version, and boot loader:

   ```nix
   { ... }:
   {
     imports = [
       ./hardware-configuration.nix
       ../../modules/core.nix
       ../../modules/hardware.nix
       ../../modules/desktop.nix
       ../../modules/development.nix
       ../../modules/home-manager.nix
       ../../modules/packages.nix
       ../../modules/users.nix
     ];

     networking.hostName = "desktop";
     system.stateVersion = "26.05";

     # Set the desktop's boot loader here.
   }
   ```
4. Add the host to `flake.nix`:
   ```nix
   desktop = mkHost ./hosts/desktop;
   ```
5. `git add hosts/desktop` — flakes ignore untracked files.
6. Install:
   ```bash
   sudo nixos-install --flake .#desktop
   ```

Home Manager applies the Niri/Noctalia setup and the curated dotfiles on the
first boot. After that:

- Create `~/.config/secrets/shell.env` with mode `600` for local database
  DSNs, if needed.
- If the desktop monitor is not `eDP-1`, adjust the output name in
  `~/.local/state/noctalia/settings.toml` and restart Noctalia.

The repo remote is private, so clone it after first boot or copy it to USB for
the install.
